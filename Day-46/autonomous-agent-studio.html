How this pipeline works

Architecture overview

Each round is a real, unrolled loop — not a fixed script. The Evaluator scores the current draft against a rubric live via the Claude API; the Critic produces a targeted critique from that score; the Improver rewrites the code using both. A stop-check runs after every round, in strict order: plateau detection (score gain < 0.3 for two consecutive rounds), threshold crossing (score ≥ your target), then a hard iteration cap as a last-resort safety valve. Whichever fires first ends the loop and hands the draft to the Final Reviewer, who never edits code — only certifies or flags it.

Extension ideas

  • Parallel evaluation ensembles — run 3 Evaluators with different rubric weightings and average/median the score to reduce single-call variance.
  • Tool-using Executor — give the Executor a sandboxed code-execution tool so it can actually run the code and report real stack traces to the Critic, not just static review.
  • Persistent cross-run memory — let the Memory Manager write learnings to a vector store so future runs on similar specs start from prior lessons instead of zero.
  • Human-in-the-loop gate — pause before Final Reviewer and let a person approve/reject/redirect, turning autonomous into supervised-autonomous.
  • Multi-file / repo-aware runs — extend the Planner to emit a file tree, and loop the Evaluator→Critic→Improver cycle per-file with a cross-file consistency check before Final Review.

Prompts for building more advanced autonomous systems

"Extend this pipeline with a tool-use step: give the Executor a JS sandbox (new Function / iframe) to actually execute generated code and feed real runtime errors into the Critic's next-round input."
"Add a branching stop-check: if Safety Monitor flags a critical issue, short-circuit straight to a Blocked state instead of continuing rounds, regardless of score."
"Turn the single-spec input into a queue, and run the whole agent pipeline autonomously across a backlog of specs, producing one final report per item."
"Add a second Evaluator with an adversarial rubric (a 'red team' scorer) and require both evaluators to agree within 1.0 point before accepting a threshold stop."
